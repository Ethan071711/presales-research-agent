# 五分钟演示：客户想给已有光伏加电池

客户需求示例：单相家庭，已有光伏，目标至少 25 kWh、套餐功率至少 8 kW，需要停电时保住部分重要负载；旧逆变器型号尚未提供。

1. 按默认表单点击“筛选公开套餐”。比较候选的功率、容量及来源。说明这是按公开套餐标签初筛，容量口径和实际系统性能仍需核实。
2. 点击某个候选的“加入询价单”，然后“整理报价草稿”。官网没有公布完整价格，因此金额为空，显示待询价。预算存在也不能据此判断足够。
3. 点击“研究此套餐”或输入问题，再开始研究。过程显示拆解、检索、证据检查、补查和成文，最终资料附原网页链接。
4. 用“资料冲突示例”查看 Fox KH 三相问题。解释供应商页面与厂家资料矛盾时为何隔离，而不是自动改一个型号。
5. 切换同组织经理，填写核对意见，确认或退回草稿。组织 B 不能读取组织 A 的运行记录；确认草稿不会给供应商发消息或下订单。

## 沿着业务读代码

| 文件 | 回答的问题 |
|---|---|
| `data/catalog.json`、`data/sources.json` | 套餐参数从哪里来，什么时候核对，有什么未确定？ |
| `presales/selection.py` | 相制、容量、功率如何筛选，为什么不能承诺旧光伏兼容？ |
| `presales/quotation.py` | 缺价、过期、设备小计和含税安装总价怎样分开？ |
| `presales/auth.py` | 谁在调用，租户和角色为什么不能由模型指定？ |
| `presales/retrieval.py` | 为什么权限筛选要在相似度和 Top K 之前？ |
| `presales/research.py` | 如何分解、补查、降级，并在重启后从图检查点恢复？ |
| `presales/api.py` | HTTP、SSE、MCP 怎样共用相同业务函数？ |
| `presales/observability.py` | 事件、人工决定、模型 token/耗时、失败及分母怎么记录？ |
| `tests/test_workflow.py` | 如何实际验证冲突、空价、隔离及恢复？ |

研究只检索当前本地资料库；运行时不会自动上网或提交询价表单。默认使用 BGE 向量和证据摘录；可选本地 Qwen 参与问题拆解与成文。模型不能给自己提升角色，也不能编造报价金额。

图最多两轮，每轮最多三个查询；异常降级保留可用证据，最后交人工审核。SQLite 检查点保存节点状态；运行中进程终止后，重启把任务标记为中断，原身份可恢复，已完成的检索无需再做。Trace 采用追加写入，故故障恢复时可能出现重放事件；检索/成文没有外部业务写入，审核动作单独防止重复提交。

PGlite 用于单机 PostgreSQL/pgvector 实测，数据库调用串行；原生 PostgreSQL 自动使用独立连接并行检索，并通过实际 SQL 时间区间重叠验证。两种模式都没有宣称生产负载性能。完整 OAuth、在线电价/补贴查询、电气设计和真实交易不在本应用范围。

Prometheus 中，`presales_stage_attempts_total` 是各类降级率的分母，`presales_http_requests_total` 是 HTTP 拒绝率分母；`presales_retrieval_unauthorized_total / presales_retrieval_candidates_total` 衡量独立权限复核发现并阻断的越权记录比例。模型延迟、token 来自实际测量；成本由 token 和配置费率估算，本地默认费率为零，未将估算称为账单。

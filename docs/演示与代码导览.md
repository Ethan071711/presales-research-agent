# 五分钟演示与代码导览

这个项目演示“给定一段需求，先找能访问的依据，再整理草稿与核算配单”。不是开放互联网搜索，也没有直接向客户发送方案或下单。

## 先演示三个动作

1. 保持“演示组织 A / 销售”。问：“星桥交换机基础版的价格和规格是什么？搭配无线接入点要注意什么？报价有效期多久？”点击开始研究，查看过程、资料和草稿。
2. 配单选基础交换机，数量 3，折扣 0.95。结果为 `1000 × 3 × 0.95 = 2850.00` 元。改为 0.90 后出现经理审批提示；加入无线接入点后出现供电兼容提示。
3. 草稿完成后，切换同组织“经理”，点击确认草稿。换成组织 B，不能读取组织 A 的运行记录或给组织 A 的产品报价。

基础模式是资料摘录，不是模型生成。设置本地模型模式后，Qwen 实际参与拆解与成文；控制台可以看到模型加载，Prometheus 记录实际生成的耗时和 token。模型不负责计算金额，也不能通过工具参数改变身份。

## 按这个顺序读代码

| 文件 | 先回答的问题 |
|---|---|
| `data/catalog.json` | 产品价格和库存从哪里来？ |
| `presales/quotation.py` | 为什么金额不交给模型算？折扣、预算、库存和兼容如何触发提示？ |
| `presales/auth.py` | JWT 验了什么？租户与角色为何不能由提问文本指定？ |
| `presales/retrieval.py` | 为什么要先选可访问资料分区，再检索并取前五？HNSW 和精确检索有什么区别？ |
| `presales/research.py` | 图有哪些节点？什么时候补查？什么时候停止？失败后如何保留可用结果？ |
| `presales/api.py` | 页面、SSE、MCP 分别怎么调用同一套检索与报价逻辑？ |
| `presales/observability.py` | 一次研究留下什么记录？审核后如何看到决定？ |
| `tests/test_workflow.py` | 如何证明越权、错误金额和异常路径被实际检查过？ |

研究过程是：**问题 → 拆解最多3个查询 → 并发派发 → 权限分区内检索 → 判断分数和缺口 → 最多补查一轮 → 摘录/模型汇总 → 人工审核。** PGlite 是单连接数据库，本地 SQL 由锁串行执行；它不能用来宣称数据库并发性能。

## 演示时要说清的边界

“这段实习真实发生过，原项目资料丢失。这个公开仓库是我在2026年10月借助AI工具重新实现的通用流程，使用模拟资料，不是公司源码。可以演示研究循环、权限检索、报价与过程记录；原来的业务效率和准确率数字没有用新模拟结果替代。”

“200条是基础合成自测，其中160条测目标资料是否进入前五，40条测跨租户和跨角色访问。它不能证明线上选型准确率，也不能证明真实客户满意度。”

“我目前还在补工程基础，会明确区分自己能讲清、能借助工具修改的部分，与尚不能独立完成的部分。”

## 练习到能自己完成

第一步，只改一个模拟产品的单价，重启演示，说明报价为何跟着变化。第二步，把销售的折扣审批线从95折改为98折，并修改对应测试的预期，解释为什么边界用例也要改。第三步，用销售令牌查询经理专用资料，指出真正生效的权限判断在哪一行。

完成后再练研究图：让检索服务报错，观察最多两轮后如何结束，并从运行记录找到降级原因。最后讲清“Recall@5”和“答案正确率”的区别。不要只背框架名。
